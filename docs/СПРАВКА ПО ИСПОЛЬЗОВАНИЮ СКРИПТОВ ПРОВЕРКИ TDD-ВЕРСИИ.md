# СПРАВКА ПО ИСПОЛЬЗОВАНИЮ СКРИПТОВ ПРОВЕРКИ TDD-ВЕРСИИ

## 📁 СТРУКТУРА ПРОЕКТА

```
project/
├── scripts/                    # Директория со скриптами проверки
│   ├── checker_main.sh         # Основной управляющий скрипт
│   ├── check_structure.sh      # Проверка структуры проекта
│   ├── check_stage0.sh         # Этап 0: Инфраструктура
│   ├── check_stage1.sh         # Этап 1: Простые структуры
│   ├── check_stage2.sh         # Этап 2: Student (ядро)
│   ├── check_stage3.sh         # Этап 3: ClassData
│   ├── check_stage4.sh         # Этап 4: SchoolData
│   ├── check_stage5.sh         # Этап 5: Вспомогательные структуры
│   ├── check_integration.sh    # Интеграционная проверка
│   └── check_criteria.sh       # Проверка критериев достижения цели
├── logs/                       # Автоматически создаваемая директория для логов
└── [остальные файлы проекта]   # Исходный код, CMakeLists.txt и т.д.
```

## 🚀 БЫСТРЫЙ СТАРТ

### 1. Настройка прав доступа
```bash
# Дать права на выполнение всем скриптам
chmod +x scripts/*.sh

# Или только основному скрипту
chmod +x scripts/checker_main.sh
```

### 2. Запуск полной проверки
```bash
# Из корневой директории проекта
./scripts/checker_main.sh
```

### 3. Просмотр результатов
```bash
# Результаты выводятся в консоль
# Детальные логи сохраняются в logs/
ls -la logs/
cat logs/full_check_*.log
```

## 📋 ОПИСАНИЕ СКРИПТОВ

### `checker_main.sh` - Основной скрипт
**Назначение:** Полная проверка всех этапов проекта  
**Что проверяет:**
- Все этапы по порядку (0-5)
- Интеграционную совместимость
- Критерии достижения цели

**Использование:**
```bash
./scripts/checker_main.sh
```

**Выходные коды:**
- `0` - все проверки пройдены успешно
- `1` - есть ошибки в проверках

### `check_structure.sh` - Проверка структуры
**Назначение:** Проверка директорий и файлов проекта  
**Что проверяет:**
- Существование всех необходимых директорий
- Наличие основных файлов
- Корректность структуры проекта

**Использование:**
```bash
./scripts/check_structure.sh
```

### `check_stage0.sh` - Этап 0: Инфраструктура
**Назначение:** Проверка инфраструктуры проекта  
**Что проверяет:**
- Файл `CMakeLists.txt`
- Настройки компиляции C++20
- Библиотеку doctest
- Базовые тесты

**Использование:**
```bash
./scripts/check_stage0.sh
```

### `check_stage1.sh` - Этап 1: Простые структуры
**Назначение:** Проверка простых структур данных  
**Что проверяет:**
- `StudentCategory.hpp` - перечисление категорий
- `FileMetadata.hpp` - метаданные файла
- `SchoolSummaryView.hpp` - сводная статистика

**Использование:**
```bash
./scripts/check_stage1.sh
```

### `check_stage2.sh` - Этап 2: Student
**Назначение:** Проверка ядра системы - структуры Student  
**Что проверяет:**
- `Student.hpp` - заголовочный файл
- `Student.cpp` - файл реализации
- Все поля (fullName, className и т.д.)
- Все методы (hasGradeTwo(), countGrades() и т.д.)
- Тесты для Student

**Использование:**
```bash
./scripts/check_stage2.sh
```

### `check_stage3.sh` - Этап 3: ClassData
**Назначение:** Проверка структуры ClassData  
**Что проверяет:**
- `ClassData.hpp` - данные класса
- Поля (className, students, subjects и т.д.)
- Методы (getTotalStudents(), getAnalyzedStudents())

**Использование:**
```bash
./scripts/check_stage3.sh
```

### `check_stage4.sh` - Этап 4: SchoolData
**Назначение:** Проверка структуры SchoolData  
**Что проверяет:**
- `SchoolData.hpp` - данные школы
- `SchoolData.cpp` - реализация
- Методы (getAvailableGrades(), getSchoolSummary())

**Использование:**
```bash
./scripts/check_stage4.sh
```

### `check_stage5.sh` - Этап 5: Вспомогательные структуры
**Назначение:** Проверка вспомогательных структур  
**Что проверяет:**
- `ITableParser.hpp` - интерфейс парсера
- Виртуальные методы
- Совместимость интерфейса

**Использование:**
```bash
./scripts/check_stage5.sh
```

### `check_integration.sh` - Интеграционная проверка
**Назначение:** Проверка совместной работы всех компонентов  
**Что проверяет:**
- Совместную компиляцию всех заголовков
- Совместимость типов данных
- Взаимосвязи между компонентами

**Использование:**
```bash
./scripts/check_integration.sh
```

### `check_criteria.sh` - Проверка критериев
**Назначение:** Проверка критериев достижения цели Дня 6  
**Что проверяет (10 критериев):**
1. Расположение файлов
2. Полнота полей структур
3. Реализация простых методов
4. Заглушки для сложных методов
5. Наличие базовых тестов
6. Использование типов C++20
7. Корректность include директив
8. Doxygen комментарии
9. Возможность компиляции
10. Соответствие архитектуре

**Использование:**
```bash
./scripts/check_criteria.sh
```

## 🔧 ПРАКТИЧЕСКИЕ СЦЕНАРИИ

### Сценарий 1: Разработка с TDD
```bash
# 1. Написать код для текущего этапа
# 2. Проверить только этот этап
./scripts/check_stage2.sh

# 3. Если есть ошибки - исправить
# 4. Проверить интеграцию
./scripts/check_integration.sh

# 5. Проверить критерии
./scripts/check_criteria.sh

# 6. Запустить полную проверку
./scripts/checker_main.sh
```

### Сценарий 2: Отладка проблем
```bash
# Если полная проверка не проходит:
./scripts/checker_main.sh

# Смотрим какие этапы не прошли
# Запускаем проблемный этап отдельно
./scripts/check_stage3.sh

# Смотрим логи
cat logs/stage3_check_*.log

# Исправляем код
# Повторяем проверку
```

### Сценарий 3: Быстрая проверка перед коммитом
```bash
# Только критерии (самое важное)
./scripts/check_criteria.sh

# Или полная проверка
./scripts/checker_main.sh
```

- 🟢 **Зеленый** - успешно пройдено
- 🔴 **Красный** - ошибка
- 🟡 **Желтый** - предупреждение
- 🔵 **Синий** - информационное сообщение

Каждый скрипт создает свой лог-файл в директории `logs/`:
- `full_check_YYYYMMDD_HHMMSS.log` - полная проверка

- `criteria_check_YYYYMMDD_HHMMSS.log` - проверка критериев

## ⚙️ НАСТРОЙКА И КОНФИГУРАЦИЯ

### Переменные окружения:
```bash
# Принудительное создание логов в другой директории
export LOGS_DIR="/var/log/project_check"
./scripts/checker_main.sh

# Отключение цветного вывода
export NO_COLOR=1
./scripts/checker_main.sh
```

### Параметры компиляции:
Скрипты используют стандартные параметры:
```bash
g++ -std=c++20 -I$PROJECT_ROOT -I$PROJECT_ROOT/third_party/doctest
```

### Требования к системе:
- Bash 4.0+
- GCC/Clang с поддержкой C++20
- Установленный doctest (в third_party/doctest)

## 🐛 УСТРАНЕНИЕ НЕИСПРАВНОСТЕЙ

### Проблема 1: "Permission denied"
```bash
# Решение:
chmod +x scripts/*.sh
```

### Проблема 2: "No such file or directory"
```bash
# Решение: убедитесь, что вы в корне проекта
pwd  # Должен показывать директорию с scripts/
ls scripts/  # Должен показывать скрипты
```

### Проблема 3: Ошибки компиляции
```bash
# 1. Проверьте установку компилятора
g++ --version

# 2. Проверьте наличие doctest
ls third_party/doctest/

# 3. Проверьте структуру проекта
./scripts/check_structure.sh
```

### Проблема 4: Скрипт зависает
```bash
# Используйте timeout
timeout 30 ./scripts/checker_main.sh
```

## 📞 ПОДДЕРЖКА

### Полезные команды для отладки:
```bash
# Просмотр всех логов
tail -f logs/*.log

# Поиск ошибок в логах
grep -r "✗" logs/

# Проверка конкретного файла
g++ -std=c++20 -I. -c src/core/Student.cpp

# Запуск без логов (только консоль)
./scripts/check_stage2.sh 2>&1 | grep -E "(✓|✗|▶)"
```

### Быстрые проверки:
```bash
# Только компиляция
g++ -std=c++20 -I. -c src/core/*.cpp

# Только тесты
cd tests && cmake .. && make && ./tests

# Минимальная проверка
./scripts/check_structure.sh && ./scripts/check_criteria.sh
```
